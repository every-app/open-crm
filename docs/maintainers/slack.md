# Slack

Team agents post to Slack through the workspace's own Slack connection (`src/server/features/slack`). An owner or admin connects it in Settings → Connections; agents (an MCP identity) can't, and the gateway refuses an agent's token exchange too.

**Credentials stay with the gateway.** The Every App gateway holds the `slack` OAuth client (`SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, set with `everyapp secret set SLACK_CLIENT_ID SLACK_CLIENT_SECRET --for gateway`). The CRM builds the authorize URL from the client's public id (`integrationStatus`), and on Slack's redirect back to `/integrations/slack/callback` it has the gateway complete `POST https://slack.com/api/oauth.v2.access` with its client (`integrationFetch`). The CRM keeps the tokens Slack issues (the bot token, and the installer's user token when granted) in `slack_connection`, encrypted under its `TOKEN_ENCRYPTION_KEY` secret (`src/server/lib/tokenCrypto.ts`), and calls Slack's Web API with them from the server only: they never reach a client, a log, the model or an MCP tool. The connect's `state` is a row minted for the person who started it, accepted once within ten minutes.

**Scopes.** The bot asks for `users:read`, `users:read.email`, `channels:read`, `groups:read`, `channels:history`, `groups:history`, `chat:write`, `chat:write.public`, `im:write`, `channels:join`, `channels:manage`, `groups:write`, `channels:write.invites`, `groups:write.invites`, `conversations.connect:write` and `links:write`; the installer's user scopes are `channels:read`, `channels:write`, `groups:read` and `groups:write` (creating private channels and adding the app to them). The settings page shows each grant in words and which ones Slack held back (`src/shared/slack.ts`). The gateway's registry entry has to list these scopes and the redirect path on the CRM's host.

**Inventory.** After a connect, on Refresh, and when the Slack status finds the members changed since the last match (a member not matched yet, or matches older than the connection, as the CRM's status checked), the CRM reads Slack's people and channels: members are matched to Slack users by exact email only, and the channel list keeps what the app is in, public channels, and (with the installer's grant) private channels it can add itself to. As in the CRM, the read is a task the dispatcher leases and retries (`slack-sync`, `SlackSyncService`), started at once, ahead of the logos, and never held for credits; one is queued or running at a time. It reads a page at a time and keeps its place on the task, so a large workspace is read over runs of about ten seconds (one a request starts ends inside its `waitUntil`), a rate limit or a failure goes on from the last page read, and a reconnect starts the read again. The builder pins a Slack destination to an id in this inventory; a run posts only there. Joining a public channel uses the bot; a private one is an invite with the installer's token, or, without that grant, the channel is marked as waiting for someone inside to invite the app. Joining and creating channels are an owner's or admin's. Members' lists (the Slack page, an agent's "Lives in", MCP), and the agent builder's for everyone, leave out the private channels the app isn't in, which only the installer's token sees. Disconnecting deletes the tokens and the channel list and keeps the matches.
